File groups are a mechanism for grouping similar types of files and environment variables within a
project using [file glob patterns or literal file paths](./file-pattern). These groups are then used
by [tasks](./task) to calculate functionality like cache computation, affected files since last
change, deterministic builds, and more.

## Configuration

File groups can be configured per project through [`moon.*`](../config/project), or for many
projects through [`.moon/tasks/**/*`](../config/tasks).

### Token functions

File groups can be referenced in [tasks](./task) using [token functions](./token). For example, the
`@group(name)` token will expand to all paths configured in the `sources` file group.

```yaml title="moon.yml"
tasks:
  build:
    command: 'vite build'
    inputs:
      - '@group(sources)'
```

## Inheritance and merging

When a file group of the same name exists in multiple [configuration files](#configuration), the
groups are _merged_ together, in the order the configs are inherited: workspace-level groups first,
then project-level groups last. By default, the inputs of each subsequent group are appended to the
inputs of the previous group. Groups that are only defined in a single config are inherited as-is.

For example, say we want to add a `lib` folder to the inherited `sources` file group, we would
define our file groups as followed.

```yaml title=".moon/tasks/all.yml"
fileGroups:
  sources:
    - 'src/**/*'
    - 'types/**/*'
  tests:
    - 'tests/**/*.test.*'
    - '**/__tests__/**/*'
```

```yaml title="moon.yml"
fileGroups:
  sources:
    - 'lib/**/*'
```

Which results in the following file groups for the project:

```yaml
fileGroups:
  # Merged with global
  sources:
    - 'src/**/*'
    - 'types/**/*'
    - 'lib/**/*'
  # Inherited as-is
  tests:
    - 'tests/**/*.test.*'
    - '**/__tests__/**/*'
```

### Merge strategies<VersionLabel version="2.5.0" />

If you'd prefer to _override_ an inherited file group instead of merging with it, for example,
because our source folder is named "lib" and not "src", the merge behavior can be customized per
project with the [`workspace.mergeStrategies.fileGroups`](../config/project#mergestrategies) setting.
This setting supports the `append` (default), `prepend`, `preserve`, and `replace`
[strategies](./task-inheritance#merge-strategies).

```yaml title="moon.yml" {2,3}
workspace:
  mergeStrategies:
    fileGroups: 'replace'

fileGroups:
  # Replaces global
  sources:
    - 'lib/**/*'
    - 'types/**/*'
```

The chosen strategy applies to all of the project's file groups, but only changes groups that are
defined in more than one config, including those defined in multiple `.moon/tasks/**/*` configs. An
empty list can be used with the `replace` strategy to remove all inputs from an inherited group.
