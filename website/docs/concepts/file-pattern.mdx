## Globs

Globs in moon are [Rust-based globs](https://github.com/olson-sean-k/wax), _not_ JavaScript-based.
This may result in different or unexpected results. The following guidelines must be met when using
globs:

- Must use forward slashes (`/`) for path separators, even on Windows.
- Must _not_ start with or use any relative path parts, `.` or `..`, except for a
  [parent traversal](#parent-traversal) segment, `...`.

### Supported syntax

- `*` - Matches zero or more characters, but does not match the `/` character. Will attempt to match
  the longest possible text (eager).
- `$` - Like `*`, but will attempt to match the shortest possible text (lazy).
- `**` - Matches zero or more directories.
- `?` - Matches exactly one character, but not `/`.
- `[abc]` - Matches one case-sensitive character listed in the brackets.
- `[!xyz]` - Like the above, but will match any character _not_ listed.
- `[a-z]` - Matches one case-sensitive character in range in the brackets.
- `[!x-z]` - Like the above, but will match any character _not_ in range.
- `{glob,glob}` - Matches one or more comma separated list of sub-glob patterns.
- `<glob:n,n>` - Matches a sub-glob within a defined bounds.
- `!` - At the start of a pattern, will negate previous positive patterns.
- `...` - As a whole path segment, matches the path after it in the directory before it, or in any
  of its parent directories. [Learn more](#parent-traversal).

### Examples

```bash
README.{md,mdx,txt}
src/**/*
tests/**/*.?js
!**/__tests__/**/*
logs/<[0-9]:4>-<[0-9]:2>-<[0-9]:2>.log
.../package.json
```

### Parent traversal<VersionLabel version="3.0.0" />

A `...` path segment matches the path after it in the directory before it, or in any parent
directory of that directory, up to the workspace root. Paths in sibling or nested directories are
never matched. This is useful for files that tools look up from the current directory, like
manifests, lockfiles, and configs.

For example, the [project relative](#project-relative) `.../package.json`, in a project at
`packages/a`, matches the following files:

- `packages/a/package.json`
- `packages/package.json`
- `package.json`

While `packages/b/package.json` and `packages/a/src/package.json` are _not_ matched.

The following rules apply:

- Only 1 `...` segment is allowed per pattern.
- A path is required after it, which may contain globs that stay within a directory, like
  `.../*.lock`, but not `**`.
- Globs are allowed before it, as each parent directory is expanded from the pattern itself, so
  `/packages/*/.../config.json` matches `packages/*/config.json`, `packages/config.json`, and
  `config.json`.
- It can be negated with a leading `!`.

Task [`outputs`](../config/project#outputs) and code [`owners`](../config/project#owners) don't
support it, as they can't be expanded. The same applies to token functions that return globs as-is,
like [`@globs`](./token#globs) and [`@group`](./token#group), outside of task inputs, as shells can't
expand them. Use [`@files`](./token#files) instead.

## Project relative

When configuring [`fileGroups`](../config/project#filegroups), [`inputs`](../config/project#inputs),
and [`outputs`](../config/project#outputs), all listed file paths and globs are relative from the
project root they will be ran in. They _must not_ traverse upwards with `..`.

```bash
# Valid
src/**/*
./src/**/*
package.json

# Invalid
../utils
```

## Workspace relative

When configuring [`fileGroups`](../config/project#filegroups), [`inputs`](../config/project#inputs),
and [`outputs`](../config/project#outputs), a listed file path or glob can be prefixed with `/` to
resolve relative from the workspace root, and _not_ the project root.

```bash
# In project
package.json

# In workspace
/package.json
```
